# Library-Playground

A personal librarian agent for your reading list.  Bring your own
library + reading history; get recommendations, taste-matched reading
lists, and a cataloguer that keeps a structured knowledge base of
every book you own.

This branch (`claude-ai-port`) ships the **claude.ai chat port** of
the librarian.  It runs on a Claude Pro subscription, no separate API
key, no Anthropic API credits beyond what Pro covers (a one-time bulk
catalogue build runs locally in Claude Code).

> **Looking for the original Claude Code workflow?**  Check out
> `main`.  The Code-side implementation stays untouched there for
> comparison; this branch is parallel, not a replacement.

## What you get

| Surface | What it does |
|---|---|
| Six skills installed in claude.ai | Auto-trigger on librarian-shaped questions, file uploads, and bulk-add requests |
| Three React artifacts (read-only renderers) | `picker` (richer batch view, opt-in), `profile` (markdown preview), `reading-list` (markdown preview) — content passed via `seed` prop, no persistence |
| Drive folder | One file: the encoded SQLite catalog |
| claude.ai project knowledge | Reading log; optional Profile / Reading_List / build_state / pending-log-updates carried across sessions |
| Local Python tooling | Bulk catalogue build + a `--sync` umbrella that refreshes the catalog from a new `Library.csv` and pushes the encoded form back to GitHub |

The reader's experience: open a chat in claude.ai, say something
library-shaped ("what should I read next year", "anything like X",
"build me a list", "is X worth my time", "I just bought Y"), and the
right skill takes over.  No commands to memorise.

## What you bring

| File | What it is | Required? |
|---|---|---|
| `Library.csv` | Your library — every book you own.  Goodreads export works directly. | Yes |
| `Reading_Log.csv` | Rated reads — what you've read, when, with stars and tags.  Goodreads export works. | Yes for full workflow; optional for casual lookups |
| `Profile.md` | Taste profile.  Generated by the librarian on first build, then updated live as you converse. | No — built for you |
| `Reading_List.md` | Your TBR pool.  Written by the librarian when you confirm picks. | No — built for you |

## How state moves between sessions

The librarian's **source of truth during a session** is `/tmp/`
working files: `Library_Catalog.sqlite`, `Profile.md`,
`Reading_List.md`, `build_state.json`, `log_pending_updates.csv`.  It
edits them in place as you converse.

At session end, the cataloguer skill **surfaces those files via
download links** (`present_files`).  You download the updated copies
and **re-upload them to project knowledge** — they're the
carry-across-sessions store.  The next session reads them back.

The three React artifacts are **pure renderers**: when you want to
look at your current profile or list, the librarian renders one
inline with the live content via the `seed` prop.  No
`window.storage`, no preflight, no publish step required.

The catalog itself lives in Drive as `Library_Catalog.sqlite.encoded`
(gzip+base64 wrapped).  The librarian reads it once at session start
into `/tmp/Library_Catalog.sqlite` and queries that.  When the
cataloguer makes in-chat edits, it presents the updated encoded file
as a download link — you replace the Drive file manually.  The Drive
connector's write path is intentionally unused, so silent agent
mutation of a shared file isn't possible.

## Setup

The full setup walkthrough lives in [`SETUP.md`](SETUP.md).  ≤30
minutes after the one-time bulk catalogue finishes.  Highlights:

1. **Prerequisites** — Pro subscription with code execution, Drive
   connector, local Python 3.11+, your Goodreads CSV exports.
2. **Clone the repo**, switch to `claude-ai-port`.
3. **Drop in your CSVs.**
4. **Run `python3 catalogue.py --library Library.csv`** to build the
   catalog (one-time, 2-6 hours unattended).
5. **Run `python3 catalogue.py --library Library.csv --sync`** to
   produce the SQLite + encoded form, write
   `dist/sync_audit.md`, and push both to your feature branch.
6. **Upload `Library_Catalog.sqlite.encoded` to a `Library-Playground`
   folder in Drive** (one file).  Upload `Reading_Log.csv` (and any
   optional `Profile.md` / `Reading_List.md` seeds) to claude.ai
   project knowledge — **as a file attachment, not as inline content**
   so it isn't auto-injected as a `<documents>` block in every chat.
7. **`make skills`** to build the six skill zips.  Upload via Settings
   → Features → Skills.
8. **Open a chat and say "build me a reading list".**  No artifact
   publish step required.  The librarian takes it from there.

## Catalog sync workflow

The Code surface owns bulk catalog work.  When you've got a new
`Library.csv` or want to re-sync everything:

```bash
python3 catalogue.py --library Library.csv --sync
```

The umbrella `--sync` mode does six things in one shot:

1. **Refreshes CSV-authoritative fields** (pages,
   goodreads_rating, goodreads_reviews) on every existing entry.
2. **Catalogues new books** in chunks of 30 (resumable on
   interruption).
3. **Runs the comparables sync** tail (canonicalise, reciprocate,
   Claude-rank top 6 when over cap).
4. **Exports `Library_Catalog.sqlite` + the encoded form.**
5. **Writes `dist/sync_audit.md`** — counts before/after,
   field-refresh stats, list of new entries, comparables stats,
   output file sizes.
6. **`git add -f` + commit + push** the encoded catalog and audit
   summary to the current feature branch (refuses `main`/`master`).
   Pass `--no-push` to skip the git step.

Then download `Library_Catalog.sqlite.encoded` from GitHub and
replace your Drive file.

The in-chat `library-cataloguer` skill on claude.ai stays focused on
**single-book / short-series** edits — adding a book you just bought,
fixing a tag, queueing a rate update.  It explicitly bounces bulk
work back to the Code-side `--sync` flow.

## Talking to the librarian

The librarian listens for the shape of your ask and routes
accordingly.  You don't pick the mode; the librarian does.

| Your ask | What happens |
|---|---|
| "What should I read next?" / "Build me a 1-year reading list" | Full workflow — triage routes to build-setup → build-batches → build-finish across multiple sessions. |
| "Anything like *Between Two Fires*?" / "Is *Hyperion* worth my time?" | Single-book mode — focused 1-3 paragraph answer, no full workflow. |
| "Tweak my list" / "swap X for Y" / "add 3 more nonfiction picks" | Refine mode — works off your existing `Reading_List.md`. |
| "Add this book" / "I bought X" / "fix this entry" | Cataloguer takes over.  Big asks bounce to `catalogue.py --sync`. |
| "Save my files" | Cataloguer surfaces `/tmp/Reading_List.md`, `Profile.md`, `build_state.json`, and any pending log updates as downloads. |

### What you control vs. what the librarian decides

- **You confirm every addition.**  The librarian never writes to
  `Reading_List.md` without an explicit pick.  Discussion isn't
  approval.  Enthusiasm isn't approval.  Wish-list mention isn't
  approval.
- **Series scope is always your call.**  When you pick a series book,
  the librarian asks how many books to add (one / first N / all
  published) before writing to the list.
- **Cap reductions are negotiated.**  If a genre cap drops mid-build,
  the librarian asks where the freed slots should go — it never
  silently shrinks the 100-book target.
- **You can correct anything mid-flow.**  Tag corrections, content
  flags, comp suggestions, "actually that's not horror it's literary
  fiction" — the librarian queues them and hands off to the
  cataloguer the same turn.

## Architecture in one paragraph

`webhelper/sqlite_export.py` converts the JSON catalog to SQLite at
build time, with `title_short` + `title_normalized` precomputed so
the runtime helper indexes subtitle-truncation cases in SQL.
`webhelper/encoded_codec.py` wraps the binary SQLite as gzip+base64
text (~5MB at 5,000 books) so the Drive connector can read it.
`webhelper/librarian_query.py` ports the Code helper to SQLite + a
stdin/stdout ledger.  Six skills under `.claude.ai/skills/` encode
the workflow phases (triage routes + does file discovery + freshness
checks + refine-vs-fresh; quickref answers single questions;
build-setup runs the interview + Phase 0; build-batches owns
Phases 1+2 with native `AskUserQuestion(multiSelect)` as the default
batch surface; build-finish closes Phases 3+4+5 and surfaces working
files for re-upload; library-cataloguer owns SQLite writes, queues
reading-log rate updates, and bounces bulk work to
`catalogue.py --sync`).  `make skills` zips each one with the three
helper modules bundled in.  Three React artifacts
(`artifacts/batch-picker.jsx`, `profile.jsx`, `reading-list.jsx`) are
pure read-only renderers that take content via a `seed` prop — no
storage, no preflight.  Storage split: Drive holds only the catalog
`.encoded`; claude.ai project knowledge holds the carry-across-
sessions copies of Reading_Log / Profile / Reading_List / build_state;
`/tmp` is the in-session working store; the cataloguer surfaces
updated files via `present_files` at session end.

For the design rationale and failure-mode handling, see
[`UX_DESIGN.md`](UX_DESIGN.md).

## Maintenance

### Adding a few books (≤3-5)

Tell the cataloguer in chat: "I just bought *Mountain Fast* by Brian
Lerner".  The cataloguer fills the entry, asks before writing, and
hands you a download link at session end.  Save the file, replace
`Library_Catalog.sqlite.encoded` in your Drive folder.

### Adding more (or re-syncing the whole library)

Update `Library.csv` locally, then run from a Claude Code session:

```bash
python3 catalogue.py --library Library.csv --sync
```

That refreshes CSV-authoritative fields, catalogues new books, runs
comparables sync, exports the encoded SQLite, writes the audit, and
pushes both to GitHub.  Download the encoded SQLite from the feature
branch and replace your Drive file.

### Updating the reading log

Either tell the librarian after finishing a book ("I finished
*Hyperion* — 5 stars") — it queues to `/tmp/log_pending_updates.csv`
and surfaces a CSV-ready paste block at session end — or replace
`Reading_Log.csv` in project knowledge with a fresh Goodreads export
and say "log refreshed".

## Hard invariants

These survive even when no skill prompt is visible.  Full spec at
`.claude.ai/skills/librarian-build-batches/SKILL.md`.  Non-negotiable:

1. Universal exclusion gate — every candidate clears
   already-read AND on-list AND shown-ledger.
2. Core target = 100 fixed.  Mid-build cap reductions trigger
   redistribution.
3. Conservative author entry-point fallback — non-Standalone book by
   an unread author requires `series_position == "Book 1"` (or
   catalog-driven entry-point fields).
4. Phase 0 unfinished-series gate before any genre batch.
5. Per-batch deep-cut floor; slot randomised; never labelled.
6. Open prose questions are turn-ending.
7. Anti-jargon contract — no internal vocabulary in chat, picker UI,
   `Reading_List.md`, or `Profile.md`.
8. Deep-cut silence — render identically across all batch positions.
9. `/tmp/Profile.md` per-edit write — silent in chat; consolidated
   diff at session end.
10. `/tmp/Reading_List.md` per-edit write — user-visible
    one-line acknowledgement.
11. Default batch-confirmation surface is native
    `AskUserQuestion(multiSelect)`; React picker is opt-in for
    cases needing richer per-book context.
12. Catalog flush is manual: cataloguer presents a download link at
    session end; the reader replaces the Drive file.
13. Working state surfaces via `present_files` at session end;
    reader re-uploads to project knowledge to carry forward.

## When the librarian isn't doing what you want

- **Books you've already read leaking through:** the exclusion gate
  uses `webhelper/librarian_query.py` with subtitle-prefix indexing
  via the SQLite `title_short` column.  If a known-read book
  surfaces, run `python3 webhelper/librarian_query.py is-read --title
  "..." --author "..." --log Reading_Log.csv` to debug.
- **Internal jargon in chat:** Invariant 7 forbids this.  Push back
  if you see "Phase 0", "ledger", "deep cut", "Bk 1", "build state",
  "encoded catalog".  The librarian should re-pitch in plain
  language.
- **Same genre cycling without learning:** after 3 rejections in the
  same cluster, the helper sets `probe_recommended: true` and the
  librarian must pause-and-probe before generating another batch.
- **Profile.md not evolving:** Profile is live memory, written
  same-turn at every reflection beat / probe / surprise / correction.
  If `/tmp/Profile.md` hasn't changed mid-build, ask the librarian to
  flush the missed signal now.
- **"Conversation too large" before any agent reply:** likely
  `Reading_Log.csv` was uploaded as inline content rather than a file
  attachment — the inline form gets injected as a `<documents>`
  block in every chat's system prompt.  Re-upload as a file.
