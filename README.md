# Library-Playground

A personal librarian agent that lives in Claude Code. Bring your own library + reading history; get recommendations, taste-matched reading lists, and a cataloguer that keeps a structured knowledge base of every book you own.

Two skills auto-trigger inside the repo:

- **`librarian`** — recommendations, "what should I read next?", "anything like X?", and full reading-list builds (Phase 0 → Phase 5 workflow).
- **`library-cataloguer`** — adding books, fixing tags, saving librarian-session corrections, looking up specific entries.

A helper script (`librarian-query.py`) is the single chokepoint for candidate generation, exclusion checks (already-read / on-list / shown-this-session), series continuation, fuzzy lookup, and live `Profile.md` writes.

---

## What you bring

| File | What it is | Required? |
|---|---|---|
| `Library.csv` | Your library — every book you own. Goodreads export works directly. | Yes |
| `Reading_Log.csv` | Rated reads — what you've read, when, with stars and tags. Goodreads export works. | Yes for full workflow; optional for casual lookups |
| `Profile.md` | Taste profile. Generated by the librarian on first build, then updated live as you converse. | No — built for you |
| `Reading_List.md` | Your TBR pool. Written by the librarian when you confirm picks. | No — built for you |

## First-time setup

### 1. Clone the repo and install Python deps

```bash
git clone https://github.com/<you>/Library-Playground.git
cd Library-Playground
pip install -r requirements.txt
```

The Python helpers run on system Python 3.11+. The `anthropic` SDK is only needed for `catalogue.py` (the bulk cataloguer); the librarian skill itself does not use it.

### 2. Drop in your `Library.csv` and `Reading_Log.csv`

Both can come straight from a Goodreads export. The cataloguer reads `Library.csv`; the librarian reads `Reading_Log.csv` for ratings, dates, and `my_tags` (your own tags).

`Library.csv` columns expected: `title`, `authors`, `genre`, `series`, `series_type`, `indie`, `classic`, plus any of `pages`, `goodreads_rating`, `goodreads_reviews` if available.

`Reading_Log.csv` columns expected: `title`, `authors`, `Last Date Read`, `My Rating`, `genre`, `series_type`, `my_tags`, `goodreads_shelves`.

### 3. Build the catalog (one-time, ~2–6 hours)

```bash
python3 catalogue.py --library Library.csv
```

This processes every book in `Library.csv` through Claude, building a deep per-book knowledge base in `Library_Catalog.json` (summary, tone, pacing, themes, comparable books, taste signals, audio suitability, content flags). Saves after every chunk; safe to interrupt and resume — already-complete entries are skipped on re-run.

For a 5,000-book library: ~200 API calls at default chunk size, 2–6 hours wall time. Auth is via your Claude Code session ingress token (no separate API key needed); script refuses to run if `ANTHROPIC_API_KEY` is set.

### 4. Run the entry-point audit (one-time, ~1–3 hours)

```bash
python3 catalogue.py --library Library.csv --audit-entry-points
```

Backfills `series_role` and `author_entry_point` fields used by the librarian's recommendation gate (e.g. so it doesn't recommend "Royal Assassin" to a reader who hasn't read "Assassin's Apprentice"). Phase 1 auto-derives ~95% of entries for free; Phase 2 routes ambiguous entries (loose-connected series like Discworld, author-flagship judgements) to the LLM.

### 5. Open the repo in Claude Code

```bash
cd Library-Playground
claude
```

Or open the project in the Claude Code web app at `claude.ai/code`. Both skills auto-trigger on librarian-shaped or cataloguer-shaped requests.

## Talking to the librarian

The librarian listens for the shape of your ask and routes accordingly. You don't pick the mode; the librarian does.

| Your ask | What happens |
|---|---|
| "What should I read next?" / "Build me a 1-year reading list" | Full workflow — Phase 0 (close out unfinished series you rated highly) → Phase 1 (high-confidence picks) → Phase 2 (genre batches) → Phase 3 (upcoming releases) → Phase 4 (final review) → Phase 5 (Top 5 capstone). 100-book core list + 10–15 stretch picks. |
| "Anything like *Between Two Fires*?" / "Is *Hyperion* worth my time?" | Single-book mode — focused 1–3 paragraph answer, no full workflow. |
| "Tweak my list" / "swap X for Y" / "add 3 more nonfiction picks" | Refine mode — works off your existing `Reading_List.md`, skips the interview and goal-setting steps. |
| "Add this book" / "I bought X" / "fix this entry" | Cataloguer takes over — adds or corrects entries in `Library_Catalog.json`. |

### What a full build looks like

A full reading-list build runs across many turns and uses the `AskUserQuestion` tool extensively. Expect:

- A short taste interview at the start (5+ multiple-choice questions across tone, pacing, character scope, context, stakes, themes; up to 2 open-ended prose questions).
- A goals conversation — how many books per genre, series-length appetite, indie/classic floors.
- Phase 0 surfaces every unfinished series you rated highly with no recent DNF signal.
- Phase 1–2 batches are sets of 3–4 books at a time, framed in chat with a paragraph per book before the picker fires.
- Reflection checkpoints every 2–3 batches — the librarian shares an observation and asks an open question; your answer goes straight into `Profile.md`.
- A `Top 5 — Start Here` capstone at the end.

### What you control vs what the librarian decides

- **You confirm every addition.** The librarian never writes to `Reading_List.md` without an explicit pick (a checked box in `AskUserQuestion`, or a clear "add it" instruction). Discussion isn't approval.
- **Series scope is always your call.** When you pick a series book, the librarian asks how many books to add (one / first N / all published) before writing to the list.
- **Cap reductions are negotiated.** If a genre cap drops mid-build, the librarian asks where the freed slots should go — it never silently shrinks the 100-book target.
- **You can correct anything mid-flow.** Tag corrections, content flags, comp suggestions, "actually that's not horror it's literary fiction" — the librarian queues these and hands off to the cataloguer the same turn.

## Interfacing tips

These are the patterns that produce the best output across smoke tests.

**1. Start with what you've read recently.** Drop in an updated `Reading_Log.csv` before the build — even a partial export of the last 3–6 months. The librarian's interview leans on rated titles, and recent reads sharpen the prompts.

**2. Be specific when something doesn't land.** "None of these landed" is fine; "the pacing's too slow for what I want right now" is better. The librarian writes your framing into `Profile.md` and adjusts the next batch around it.

**3. Correct in flight.** If the librarian rates a book ★★ and you actually loved its precursor, say so immediately ("I loved Eragon"). It will re-rate and ask what it misread — that signal updates your profile too.

**4. Don't worry about going long on series.** Phases 1–2 have a 10-book grace cushion above the 100 target — series suggestions that tip you to 103 are fine. The cap conversation only opens once core ≥ 100.

**5. Skipping a whole batch is its own signal.** When you check none of the 4 picks, the librarian pauses and probes what's off about the framing — not what's off about the four books. Use that to redirect the genre or tone.

**6. Use the helper from the command line for diagnostics.** A few useful one-liners:

```bash
# Has the librarian seen this book?
python3 librarian-query.py is-read --title "The Shining" --author "Stephen King"

# Find a book by partial title or series name
python3 librarian-query.py lookup --query "Cesare Aldo"

# What series am I mid-way through that I'd plausibly want to continue?
python3 librarian-query.py unfinished-series

# What's the next book after this one in its series?
python3 librarian-query.py series-continuation \
    --title "A Little Hatred" --author "Joe Abercrombie"

# Distribution warning — heads-up about cross-cutting concentration
python3 librarian-query.py distribution
```

**7. Commit at phase boundaries.** The librarian offers `Want me to commit progress?` between phases. Saying yes gives you a git history that mirrors the build, which is useful for going back to inspect what changed.

## Maintenance

### Adding a few books

Tell the cataloguer in chat: "I bought *Between Two Fires*", "add *The Lesser Dead* by Christopher Buehlman". It looks up the book, fills the catalog entry, and writes after you confirm the change.

For more than ~10 books at once, update `Library.csv` directly and run:

```bash
python3 catalogue.py --library Library.csv
```

The script detects new rows, adds them as pending, and processes only the new ones.

### Fixing tags or content flags

"Actually *Cloud Atlas* is literary fiction not science fiction" — the cataloguer applies the change, regenerates the slim browse index, and offers to commit.

### Refreshing comparable books

```bash
python3 catalogue.py --library Library.csv --sync-comparables
```

Canonicalises title variants, reciprocates links between matched pairs, and asks Claude to pick the strongest 6 comps when a book has too many.

### Re-running entry-point audit

```bash
python3 catalogue.py --library Library.csv --audit-entry-points
```

Re-runs only on entries with null `series_role` or `author_entry_point`. Idempotent — already-filled entries are skipped.

## When the librarian isn't doing what you want

A second smoke-test surfaced patterns worth knowing about up front. They're addressed in the current spec, but if you see a regression:

- **Books you've already read leaking through:** the exclusion gate uses `librarian-query.py` with subtitle-prefix indexing. Subtitle truncation in `Reading_Log.csv` (`Side Jobs` vs `Side Jobs: Stories from the Dresden Files`) should resolve cleanly. If a known-read book surfaces, run `python3 librarian-query.py is-read --title "..." --author "..."` to debug the normalization.

- **Internal jargon in chat ("Phase 0", "ledger", "Bk 1", "deep cut"):** Invariant 7 forbids this. Push back if you see it — the librarian should re-pitch in plain language.

- **Same genre/cluster cycling without learning:** after 3 rejections in the same cluster (genre × indie/classic × page bucket), the helper sets `probe_recommended: true` and the librarian must pause-and-probe before generating another batch. If you've passed on 3 indie-fantasy picks and a 4th comes, ask "are we probing the framing yet?".

- **Profile.md not evolving:** Profile is live memory, written same-turn at every reflection beat / probe / surprise / correction. If it's empty or hasn't changed mid-build, ask the librarian to flush the missed signal now.
